### Постановка задачи

Дан массив точек с координатами `(x, y, z)`. Необходимо найти три точки, образующие треугольник максимальной площади.

Реализовать многопоточную обработку данных на языке C. Максимальное количество потоков задаётся ключом запуска программы.

Исследовать зависимость ускорения и эффективности от количества потоков и размера входных данных.

### Алгоритм решения

1. Программа считывает количество точек и их координаты.
2. Создаёт рабочие потоки через `pthread_create`. Главный поток также участвует в вычислениях.
3. Потоки получают задания через общий счётчик, защищённый `pthread_mutex_t`.
4. Каждый поток перебирает выделенные ему комбинации точек, вычисляет площади треугольников через векторное произведение и сохраняет свой локальный максимум.
5. Главный поток ожидает остальные через `pthread_join`, сравнивает их результаты и выводит треугольник максимальной площади.

Мьютекс используется только при получении следующего задания. Вычисления выполняются независимо, поэтому дополнительная синхронизация не требуется.

Программа запрашивает количество точек, затем координаты каждой точки.

### Исследование ускорения и эффективности

Использовались массивы из 500, 1000 и 1500 точек. Для каждого размера проверены 1, 2, 4, 8 и 16 потоков.

Для каждого количества потоков выполнен один прогревочный запуск и пять измерений, по которым рассчитано среднее время. Входные данные для сравнений одинаковые. Время чтения и вывода данных в измерения не входит.

Ускорение: `S(p) = T(1) / T(p)`

Эффективность: `E(p) = S(p) / p × 100%`

Где `T(1)` — время выполнения на одном потоке, `T(p)` — время на `p` потоках.

| 500 | 4 | 0.005385 | 3.56 | 88.9% |
| 500 | 8 | 0.003052 | 6.27 | 78.4% |
| 500 | 16 | 0.002497 | 7.67 | 47.9% |
| 1000 | 1 | 0.157113 | 1.00 | 100.0% |

С увеличением количества потоков время вычислений уменьшается, однако ускорение не является линейным.

На небольших массивах заметнее накладные расходы на создание потоков и синхронизацию. При 16 потоках эффективность снижается из-за ограниченного количества вычислительных ресурсов и конкуренции потоков за них.

При увеличении размера массива многопоточность используется эффективнее, так как на каждый поток приходится больше вычислений.

Проведено исследование ускорения и эффективности при разных размерах входных данных и количестве потоков. Максимальное полученное ускорение — **10.51 раза на 16 потоках** для массива из 1500 точек.

На практике изучены создание и ожидание потоков, синхронизация доступа к общей памяти и влияние многопоточности на производительность.
